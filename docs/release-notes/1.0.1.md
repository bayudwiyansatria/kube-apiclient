# Kube API Client - Release Notes

## Version 1.0.1

### 📅 Release Date

2026-10-03

### 📖 Overview

Kube API Client 1.0.1 adds Kubernetes Secret upsert support. This release also introduces namespace-scoped Helm RBAC and aligns the container workflows so Docker Hub and GitHub Container Registry receive the same built image digest.

### 🚀 Key Features

- **Secret Upsert**
  - Implemented `PUT /api/v1/secret/{namespace}/{name}` as an idempotent upsert operation
  - Creates a Kubernetes Secret when it does not exist
  - Replaces the type and data of an existing Secret while preserving its Kubernetes metadata
  - Accepts Kubernetes Secret type values such as `Opaque`

- **Kubernetes Integration**
  - Uses the in-cluster service account when no explicit kubeconfig path is configured
  - Added namespace-scoped `Role` and `RoleBinding` resources
  - Added configurable `rbac.create` and `rbac.targetNamespaces` Helm values
  - Grants `get`, `create`, and `update` access to Secrets in explicitly configured namespaces

- **Container Publishing**
  - Builds one container image for Docker Hub and GitHub Container Registry
  - Publishes commit candidates using the Git short SHA
  - Promotes the existing candidate image to the release version without rebuilding it
  - Verifies that both registries reference the same image digest

- **Security**
  - Added secret detection to the main and release workflows
  - Blocks build, test, documentation, version, and release work when potential credentials are detected
  - Uploads the redacted Gitleaks report as a short-lived workflow artifact

- **Documentation**
  - Documented in-cluster service-account authentication
  - Documented the Secret upsert endpoint and namespace-scoped RBAC configuration

### 🔧 Technical Details

- **Dependencies**
  - Spring Boot 3.x
  - Official Kubernetes Java Client
  - SpringDoc OpenAPI
  - Spring Security
  - OpenJDK 21 container runtime

- **Requirements**
  - Java 17 or higher
  - Maven 3.6+
  - Kubernetes cluster access
  - A service account with Secret access in every configured target namespace

### 📝 Configuration

```yaml
serviceAccount:
  create: true
  automount: true

rbac:
  create: true
  targetNamespaces:
    - mysql
    - kube-system
```

When running inside Kubernetes, leave `KUBERNETES_CONFIG_FILE_PATH` unset so the application uses its mounted service-account credentials. Set it only when running locally with an explicit kubeconfig file.

### 🐛 Bug Fixes

- Replaced the unimplemented Secret update endpoint with a functional create-or-update operation
- Returned the actual service response status from the Secret upsert endpoint
- Added case-insensitive conversion from Kubernetes Secret type values to the internal Secret type enum
- Added the RBAC resources required for in-cluster Secret reconciliation
- Replaced the unavailable `openjdk:21-slim-buster` tag with `openjdk:21-ea-34-jdk-slim-bookworm`

### 🔜 Upcoming Features

- Additional Kubernetes resource support
- Metrics and monitoring for reconciliation operations
- Expanded API integration tests

### 🚨 Known Issues

- Every namespace managed through the Secret endpoint must be listed under `rbac.targetNamespaces`
- Container release promotion requires the matching Git short-SHA candidate image to exist in both registries
